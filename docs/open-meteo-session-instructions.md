## 4. 第 1 部: 接続の使い回し

### 4.1 Open-Meteo(`cloud_forecast.py`)

- プロセスの中で 1 つの `requests.Session` を持ち、`_fetch_hourly_detailed` の通信をそこに通す。最初の通信のときに作る。
  形はヤマビヨリ `mountain_weather_core.py` の `_http_session()` と同じ考え方でよい(コードは写さず、ホシビヨリの書き方で書く)。
- User-Agent は今の文字列のまま、送られ続けること(Session に付けても、通信ごとに渡してもよい)。
- 接続が切れたあとの張り直しは requests に任せる。張り直しのための独自の処理は足さない。

### 4.2 ひまわり画像(`himawari_image.py`)

- `_http_get` も同じく 1 つの Session を使い回す。相手のホストが違うので、Open-Meteo とは別の Session でよい。
- User-Agent・再試行・429 と 4xx の扱いは今のまま。

### 4.3 テスト

- `tests/test_fetch_failures.py` と `tests/test_himawari_*.py` は `requests.get` を差し替えている。Session に合わせて直す。
  今ある検査の中身(200・429 は再試行しない・400 は再試行しない・408 と 500 は再試行・接続エラー 3 回・後方互換)は減らさない。
- 足すテスト: 2 回続けて取得したとき、同じ Session が使われること。User-Agent が送られること。

## 5. 第 2 部: 時間の計測の表示

- `grid_cache.py` の `GridCloudCache` と `FetchSummary` に、次を数えて持たせる。
  - 通信にかかった秒数の合計(再試行と、再試行の間の待ちを含む)
  - 再試行した回数
  - 失敗した試行(成功する前の失敗も含む)にかかった秒数の合計
- `FetchOutcome` に、試行の回数と秒数を入れて返す形でよい。
- `FetchSummary.console_line()` の今の文はそのまま残し、後ろに足す。例:
  `… / 通信 132.4 秒(うち失敗の待ち 40.2 秒・再試行 2 回)`
- `explore_hoshibiyori.py` と `generate_report.py` の最後に、全体の秒数と、通信以外の秒数(全体 − 通信)を 1 行で出す。
- レポート(HTML)の中身には出さない。画面の表示だけ。
- テスト: 数えた値が `FetchSummary` に入ること、`console_line()` に出ること(時計は差し替える)。
