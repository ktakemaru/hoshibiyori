### 同じ「地形データが無ければ通す」がほかにあるか(調べただけで、直していない)

- **独自に同じ判定をしている場所: なし。** `profile is None`・`clears_horizon`・`terrain_available`・`horizon_alt`・「地形データ」の語で、`tests/` を除く全部の `.py` を探した。`explore_hoshibiyori.py` の外には無かった。

- **参考:** `generate_report.py` の一般的な「見どころ」ガイド(`build_sky_guide` まわり)と、星空ガイド(`skyguide/`)。
  - `generate_report.py` のガイドは、もともと平坦な地平線と仰角の閾値で判定している。地点の地形は使わない設計。
  - 星空ガイドは、稜線のデータが無い地点ではエラーで止まる(`skyguide/build.py` 127 行目)。

## 6. コンシェル側への申し送り

- 天の川モードの JSON(`finals`・`outlooks`)に、**地形データが無く銀河中心が 0° 以下の候補は出なくなった**。前回の報告書の「`target_alt` が正かどうかを見る必要がある」という注意は、この変更が入れば不要になる。ただし古い JSON を読む場合は、引き続き見ること。
- `terrain_available: false` の候補は、「地形の稜線は見ていないが、0° の地平線より上には出る」という意味になった。山に囲まれた地点では、実際には稜線に隠れている可能性がある。
- `horizon_alt` は、地形データが無い候補では従来どおり `null`(0 は入らない)。
- 天の川モードで候補が 0 件の季節が増える。そのときは星空・星座モード(`--target stars`)の結果を使う。画面にも、その案内の1行が出る。
- JSON の形(項目・スキーマ)は、この部では変えていない。
