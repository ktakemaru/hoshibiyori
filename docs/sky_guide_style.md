# 星空ガイド 解説JSONの書き方

星空ガイド(星空シミュレーター付き)は、次の3層で作る。**HTMLは手で書かない。数値はエージェントが書かない。**

1. **数値JSON**(`hoshibiyori-skyguide-data/1`): `scripts/make_sky_guide.py` が既存ロジックで作る。
2. **解説JSON**(`hoshibiyori-skyguide-commentary/1`): エージェントが書く(この文書)。
3. **描画**: `scripts/render_sky_guide.py` が、固定のテンプレートに2つのJSONを差し込んで1ファイルのHTMLにする。

見本: `tests/fixtures/sky_guide/senjogahara_20261009_commentary.json`(戦場ヶ原 2026-10-09)。見本のHTMLは `docs/examples/`(読み取り専用)。

## 手順

```powershell
# 1. 数値JSON(通信しない。雲量はキャッシュにあれば入り、無ければ理由つきで省略される)
.\.venv\Scripts\python.exe -X utf8 scripts\make_sky_guide.py --spot 戦場ヶ原 --date 2026-10-09 --json-out out\senjogahara_data.json
# 2. 解説JSONを out\senjogahara_commentary.json に書く(下記)
# 3. 描画(解説の時刻の言い回しの機械照合つき。食い違いがあれば出力されない。数値の食い違いも既定で止まる。警告だけにするなら --warn-numbers)
.\.venv\Scripts\python.exe -X utf8 scripts\render_sky_guide.py --data out\senjogahara_data.json --commentary out\senjogahara_commentary.json --out out\senjogahara.html
```

- `--estimate` を付けると、通信が要る見込み(未キャッシュの雲量セル数・稜線CSVの有無)だけを表示して終了する。
- 通信が要る処理(`--cloud fetch --allow-network`)は、**所要時間とリクエスト数の見込みをユーザーに伝えて承認を得てから**行う。
- 一覧(`stargazing_spots.json`)にない地点は `--name --lat --lon --elevation --horizon-csv`。稜線CSVは `step2_terrain` の既存ツールで作る
  (国土地理院のDEMタイルの取得=通信が要る)。

## 解説JSONの項目(必須は ★)

| 項目 | 内容 |
|---|---|
| `schema` ★ | `hoshibiyori-skyguide-commentary/1` |
| `lead` ★ | リード文(2〜3文)。この夜の見どころ |
| `facts` ★ | 「この夜の条件」**ちょうど4項目**。各 `{key, value, sub}`(例: 暗くなる時間 / 月 / 雲 / 天の川の中心部) |
| `cards` ★ | 狙える構図(1件以上)。`{id, when, time, az, frame:{az,alt,w,h,lens}, title, tags:[[文字,"hot"/"hard"/""]], body, list:[…]}`。`time` は数値JSONの `times` のどれか、`az` は0以上360未満 |
| `directions` ★ | 周囲の山と方位の表(1件以上)。`{label, elevation, terrain, sky}`。`terrain` の `**山名**` は太字になる |
| `tips` ★ | 撮影メモ(1件以上)。`{title, body}` |
| `peaks` | パノラマに出す山名。`{az, name, basis}`。`basis` は `確認済み` か `推定`(必須)。`az` は数値JSONの `peak_candidates` の方位と3°以内 |
| `heading` / `title` | 見出し・ページ題(省略時は「<地点名>の星空」「<地点名> 星空ガイド」) |
| `initial_time` | シミュレーターの初期時刻(`times` のどれか。省略時は夜の中央) |
| `cloud_note` / `cards_lead` / `directions_note` | 補足文(省略時は既定文) |

必須要素(星空シミュレーター・事実4項目・構図カード・周囲の山と方位の表・撮影メモ・出典と免責)が欠けると描画はエラーになる。

## 書いてよい数値の出どころ

文章に入れる数値は、**数値JSONの `events` と `frames` から取る**。覚えや推測で書かない。

- `events`(決定論。同じ入力で同じ結果): 暗い時間帯、天の川の中心が稜線の上にいる区間と最大高度(`gc_above_ridge`)、主な天体・惑星が稜線の上にいる区間と
  昇る・沈む時刻と方位(`star_above_ridge`・`planet_above_ridge`)、北極星の高度(`polaris_altitude`)、月が出ている区間(`moon_up` / `moon_below_horizon_all_night`)。
- `frames[i]`: 時刻 `times[i]` の全天(各天体の[方位,高度]、月の方位・高度・輝面比・満ち欠けの向き)。
- `horizon_deg[方位]`: 方位1°ごとの稜線の仰角。`peak_candidates`: 稜線の極大(山名は付いていない)。
- 雲量: `cloud.hours`(あれば)。

### 時刻の言い回しの規則(機械照合される)

`events` の「稜線の上」は稜線(`horizon_deg`)を基準にしている。「昇る時刻」は地平線ではなく稜線を越える時刻、「沈む・隠れる時刻」は稜線に隠れる時刻。
解説の文に「◯◯が昇る・沈む・隠れる」と時刻の言い回しを書くと、描画の前に `events` と**機械照合**される(`scripts/check_sky_guide_text.py`。`render_sky_guide.py` も既定で実行し、
食い違いがあれば出力しない)。言い回しの範囲は次のとおり。

| 言い回し | 実際の時刻の範囲 |
|---|---|
| N時M分ごろ | N:M の前後10分以内 |
| N時すぎ | N:00 以上 N:30 未満 |
| N時前 | N:00 の30分前以上 N:00 未満 |
| N時ごろ | N:00 の前後30分以内 |
| N時台 | N:00 以上 N+1:00 未満 |

- 例: 稜線を越える時刻が 01:57 の木星は「2時前」。「1時すぎ」ではない。00:53 の火星は「1時前」(「0時すぎ」ではない)。
  見本の元の文章はこの2か所が合っておらず、時刻の言い回しだけ訂正した版が `docs/examples/senjogahara_20261009_commentary_corrected.json`、数値(高度・方位表の稜線の仰角)も直した**手本**が `docs/examples/senjogahara_20261009_commentary_corrected_v2.json`(元のゴールデンは回帰テスト用に元のまま)。
- 迷ったら、`events` の時刻をそのまま書く(「00:53に稜線を越える」など)。
- 時刻の言い回しの照合の対象外(検査されないので、`events` と `frames` から取って書く): 天体名のない文、昇る・沈む・隠れる等の動詞のない文、`events` にない天体
  (等級2.0より暗い恒星)、「N時に」「N時から」の言い方。高度・方位・稜線の仰角は、次の「数値の照合」が見る。

### 数値の照合(`skyguide/check_numbers.py`)

2026-10-17の実例(みずがき山自然公園)で、時刻の言い回しの照合を通ったのに、カードの高度が別の時刻のフレームの値だった、方位表の仰角が `horizon_deg` と合わなかった、
「明け方にシリウスが昇る」(events上は01:04)と書いた、輝面38%の月を「細い月」と書いた、という誤りが残った。次の4種類を足した(Finding の `kind` で見分ける)。

| kind | 見るもの | 書き方の決まり |
|---|---|---|
| `altitude` | 「天体名(16方位の高度N°)」「天体名は…16方位の高度N°」の方位名と高度 | **カードの高度は `card.time` のフレームから取る**。別の時刻の値を書くときは文中に「21時20分」のように時刻を書く。方位は16方位名(北・北北東・北東…)、高度は±1°以内 |
| `ridge_range` | 方位表の `label` の方位範囲(「北 345〜15°」)と `elevation`、本文中の「南西(210〜255°)の稜線は1〜4°」 | **方位表の仰角は補助スクリプトで出す**。本文で稜線の仰角を書くときは、**方位範囲を併記する**(併記が無い「南西の稜線は1〜4°」は検査されない) |
| `vague_time` | 天体名+昇る・沈む・隠れる・越える等の動詞がある節の「明け方・未明・夜半・宵・夕方」等 | **曖昧な時間語を使わない**。`events` の時刻を数字で書く(「シリウスは01:04に稜線を越える」)。動詞の無い「明け方のオリオン座」は検査されない |
| `moon_adjective`(警告) | 月が出ている間の輝面が30%を超える夜の「細い月・三日月」 | 輝面の数字か「上弦前の月」などにする。警告で、出力は止めない |
| `altitude_range` | 天体名に結びつく「高度A〜B°」(時間帯にわたる範囲。「すばる(高度50〜60°)」) | **カードの `when`(「HH:MM〜HH:MM」)の時間帯の最小〜最大**を `--time-range` で引いて書く。節に2つの時刻(「23時20分から0時10分のすばる(高度50〜60°)」)があればその区間。下限・上限とも±1°以内 |
| `ridge_range_loose` | 方位範囲を併記しない「南東〜南は稜線が1〜4°」 | 方位表の label が同じ方位名の行(1行だけのとき)の方位範囲の計算値と一致させる。方位名は label と同じ書き方(「南東〜南」)にする。方位範囲を併記すれば、既存の `ridge_range` が照合する |

数値は補助スクリプトで引く(通信しない)。覚えや推測、別の時刻のフレームの値を書かない。

```powershell
# 方位範囲の稜線の仰角(360°をまたぐ範囲も可)
.\.venv\Scripts\python.exe -X utf8 scripts\sky_lookup.py --data out\xxx_data.json --az 345 15
# ある時刻の天体の方位(16方位)と高度。時刻は数値JSONの times のどれか
.\.venv\Scripts\python.exe -X utf8 scripts\sky_lookup.py --data out\xxx_data.json --time 21:40 --names アルタイル ベガ デネブ
# 時間帯の天体の高度の最小〜最大(日付またぎ可。端は隣り合うフレーム間の直線補間、0°未満は0°で切る)
.\.venv\Scripts\python.exe -X utf8 scripts\sky_lookup.py --data out\xxx_data.json --time-range 23:20 00:10 --names すばる 木星
```

- 時刻の決め方: 節(読点で区切った部分)の中の「N時M分」「N時半」「N時」。無ければ、それより前の節の時刻、それも無ければ `card.time`。
  カード以外の項目(リード・方位表・撮影メモ)で時刻が無い文は検査されない。「N時台」「N時すぎ」のように幅のある言い方の節も検査されない。
- 検査されないもの: 天体名の無い文、`frames` に無い天体、フレームの時刻から10分以上離れた時刻、方位名が表の1行に決まらない稜線の仰角、雲量・輝面・距離など高度以外の数値。
  高度の範囲(`altitude_range`)は、時間帯が決まらないとき(節の時刻が1つだけ・文の別の節に時刻がある・`when` が「終夜」など時刻でない・カード以外で時刻が無い・「N時台」)、
  天体名が高度の直前に無いとき、天体名と高度の間に「稜線・山・仰角」などの語があるとき(地形の高さ)は検査されない。
- `render_sky_guide.py` は、既定でエラー扱いの数値の食い違いがあれば出力しない(終了コード1。月の形容は警告で止めない)。警告表示だけにしたいときは `--warn-numbers`。
  `--strict-numbers` は互換のために受け付けるが何もしない。`--no-check-text` は従来どおり、すべての照合を省く。`scripts/check_sky_guide_text.py --numbers` で、描画せずに数値も照合できる。
- 手本は `docs/examples/senjogahara_20261009_commentary_corrected_v2.json`(読み取り専用。新しい検査でエラー・警告とも0件)。
  旧い `..._corrected.json` は時刻の言い回しだけ訂正した版で、新しい検査では方位表の仰角5行・アルタイルとベガの高度・天の川の中心部の高度が食い違うため、手本にしない。

## 恒星カタログの出典(未照合の注意)

シミュレーターの恒星・星団・銀河の座標は `skyguide/objects.json`(J2000.0、固有運動は無視)。各天体の出典は「標準的な恒星カタログ値の手入力」で、
**Hipparcos との機械照合は未実施**。見本の天体位置との最大差は0.11°で、`step1_astronomy/targets.json` と重なる天体とも一致するが、
同じ標準値どうしの一致であり、独立した出典との照合ではない。天体の座標そのものを文章で断定しない(位置は `frames` の値を使う)。

## 山の名前

- 山名は方位・距離からの**推定**。確認できていない山は `basis: "推定"` とし、表の文章にも「推定」「〜方面」と書く。
- `確認済み` にしてよいのは、方位・標高・距離が地図と一致して確認できたものだけ(見本では男体山)。確認方法を覚えていなければ `推定` にする。
- 山名が分からないピークは、名前を付けず方位と仰角だけを書く(`peaks` に入れない)。

## 雲量について

- 雲量は**全天の平均**の視界遮蔽雲量(観測者より上の雲)。**どの方角に雲が残るかは分からない**。文章で方角の雲を断定しない。
- 予報が取れない日付(過去・約2週間より先)や、通信しない設定でキャッシュが無いときは、雲量を省略してよい。理由はページに表示される(`cloud_omitted_reason`)。
  その場合、`facts` の「雲」には「予報なし」と書き、雲について推測を書かない。

## 月

月がある夜は、シミュレーターが月(月相つき)を描き、読み出しに高度・方位・輝面を出す。月明かりは天の川に直結するので、`facts` の「月」と構図の `body` に、
`events` の `moon_up`(出ている区間と最大高度)と `frames[*].moon.illum`(輝面比)から書く。
