### 5. A: 走査した全部の夜と、外れた理由

**今の状態**: JSON の `nights` には、候補になった夜(月の影響が小さい時間帯が長い順の上位 `NUM_CANDIDATE_NIGHTS` 夜)だけが入っている。走査した `NUM_NIGHTS_TO_SCAN` 夜のうち、外れた夜の情報が無い。

**なぜ要るか**: コンシェルが「今週末は月が明るいので、星空には向きません」と根拠つきで言うには、外れた夜とその理由が要る。今のままだと「調べていない」のか「調べたが外れた」のかが区別できない。

**作るもの**:

- JSON に `scanned_nights` を足す(**項目の追加だけ。`nights` はそのまま残す。スキーマの名前は `hoshibiyori-explore/1` のまま**)。
- 中身は、走査した全部の夜を日付順に。各夜に、`NightCandidate` と同じ項目(値が無い項目は `null`)と、次を入れる:

  - `regime`: 選ばれた夜だけ `MSM` / `ECMWF`。選ばれていない夜は `null`

- 理由のコードは、コードの実際の分かれ方(`stage1_moon_filter` の `continue` と、上位 N 夜の切り捨て)から決める。想定は次の 3 つ。実際の分かれ方と違えば、実際に合わせて名前を決め、報告書に書く。

  - `no_moon_free_window`: 月の影響が小さい時間帯が無い
  - `not_in_top_n`: 時間帯はあるが、長さの順で上位 N 夜に入らなかった
- 既存の `all_nights_timeline()`(全部の夜を日付順に評価する関数。HTML レポート用)が使えるか、まず読む。使えるなら使う。

## 第 2 部(ブランチ `fix/no-terrain-horizon`。`git switch main` → `git switch -c fix/no-terrain-horizon`)

### 10. 何が起きているか

天の川モードでは、対象(銀河中心)がその地点の地形の稜線より上に出るかを確かめている。地形地平線のデータ(horizon CSV)がある地点は 897 件中 88 件だけで、**データの無い地点は、高度を見ずに「見える」扱いになっている。**

- 近日中の候補(`stage3_direction_filter`): 地形データが無いと `clears_horizon = True`(コメントに「地形データが無いため判定をスキップ(暫定): 通過扱いとし、結果に明示する」)。
- 見込み(`stage_outlook` → `compute_target_window`): `profile` が `None` なら `visible = True`。

その結果、銀河中心が夜のあいだ地平線の下にある時期(晩秋〜冬)でも、地形データの無い地点が候補に残る。2026-11-13 の固定キャッシュでは、天の川モードの見込み 360 件が、すべて「地形データが無く、銀河中心の高度が 0° 以下」だった(#34 の報告書)。画面は上位しか出さないので目立たなかったが、JSON は全件を出すので、コンシェルがそのまま誤ったおすすめの材料にしてしまう。

### 11. 直し方(利用者が承認した範囲。これ以外の判定は変えない)

**考え方**: 地形データが無い地点は、「地平線が水平(高度 0°)」として扱う。地形があれば稜線はそれより高いので、0° は「これより下では絶対に見えない」という下限になる。**新しい閾値は作らない**(「5° 以上」などの値を決めない。0° だけ)。

変えるのは次の 2 か所だけ:

1. `compute_target_window`: `profile` が `None` のとき、`visible = True` を「高度が 0° より上のときだけ見える」に変える。
2. `stage3_direction_filter`: 地形データが無いとき、`clears_horizon = True` を「最も高い時刻の高度が 0° より上のときだけ通す」に変える。

決まり:

- 地形データがある地点の判定は変えない。
- 星空・星座モード(`--target stars`)は銀河中心を評価しないので、動きを変えない。出力が 1 文字も変わらないこと。
- `terrain_available` は今までどおり(地形データが無い地点は False)。`horizon_alt` も今までどおり(`None`)。0 を入れない。
- スコア式は変えない。スコアの中の `max(0.0, best_alt - (h_alt or 0.0))` などの行に触れない。
- 画面の「うち地形データなし(…地形チェック未実施・暫定通過)」の行は、意味が変わるので文を直す(例: 「地形データなし(地平線を高度0°として判定)」)。件数の数え方は、「地形データが無く、0° の判定を通った件数」にする。文は 1 行だけ直し、ほかの行は変えない。
- コードのコメントに、この判定の理由と日付(2026-11-16、利用者の承認)を書く。
- 同じ「地形データが無ければ通す」が `generate_report.py` やほかのスクリプトにもあるかを調べる(`compute_target_window`・`clears_horizon`・`profile is None` などで探す)。**あっても直さず**、場所と中身を報告書に書く(直す範囲は上の 2 か所だけ)。

### 12. 第 2 部のテストと確かめ
