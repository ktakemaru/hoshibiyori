## 6. メモリ停止の調査(続きの作業・手順1)

**結論: 比較スクリプトはメモリを多く使わない。停止の原因は、スクリプト自身ではなくシステム全体のメモリ逼迫と考えられる(確証ではない)。**

- 環境: 物理メモリ 7.9GB、調査開始時の空きは約 2.0GB(`claude` 3プロセス計約1GB、メモリ圧縮約1GB、メールソフト・ウイルス対策・ブラウザ等が常駐)。
- 測定方法: `scripts/measure_peak_memory.py`(子プロセスの PeakWorkingSetSize / PeakPagefileUsage を0.2秒ごとに読む。最初は `py` ランチャーの子を測って10MBと小さすぎたため、実体の `python.exe` を直接指定して測り直した)。
- 実測(`compare_lp_sources.py`、主軸のみ):

| 対象 | ピーク物理メモリ | ピークコミット | 所要 |
|---|---|---|---|
| 6地点・1夜 | 54MB | 172MB | 19.6秒 |
| 24地点・2夜 | 59MB | 177MB | 54.3秒 |
| **146地点・全夜(本番)** | **83MB** | **199MB** | **838.8秒** |
| `generate_report.py`(legacy、146地点) | 95MB | 213MB | 708.2秒 |
| `generate_report.py --lp-source bm` | 101MB | 215MB | 663.9秒 |

- 地点数に対するピークの伸びは約0.2MB/地点で、**メモリが地点数に比例して膨らむ様子はない**(6→24→146地点で54→59→83MB)。
- 停止された最初の実行は、**参考候補(OSM展望データ751件)を含む全897件**が対象だった(`generate_report.py` は主軸146件のみ)。897件の外挿は約230MBで、これも大きくない(外挿であり実測していない。897件の実行はしていない)。
- 停止された2件のうち1件は、**ファイルの出現を待つだけの `until ... sleep` のシェルループ**だった。これはほぼメモリを使わない。したがって停止は「そのスクリプトがメモリを食った」ではなく、**システム全体が逼迫していたときに、バックグラウンドコマンドがまとめて停止された**という説明が最も整合する。
- 直したこと: 原因がスクリプトのメモリ消費ではないため、メモリ削減の修正は不要と判断し、**入れていない**。代わりに、(1) 比較スクリプトの既定の対象を `generate_report.py` と同じ**主軸146件のみ**に揃えた(参考候補を含めるのは `--include-reference`。実行時間・通信を無駄に増やさないため)、(2) `--sites-limit`/`--nights-limit` を足した。

- **近傍(0〜20km)の寄与割合**が最も強く効く(相関 −0.61、単独で決定係数約0.37)。近傍の寄与が10%未満の32地点は平均 +8.9pt(新指数で明るい)、40%超の35地点は平均 −6.3pt(新指数で暗い)。標高と近傍割合を一緒にしても決定係数は0.40で、標高が足す説明力はわずか(標高と近傍割合は互いに関連している可能性がある)。
- **特定都市との距離**(東京・最寄りの基準都市まで)は、順位差とほぼ無関係(|相関|≦0.13)。**100km超からの遠方寄与の割合**も無関係(−0.06)。
- 標高・近傍割合・東京距離・遠方割合の4つを合わせても決定係数は約0.51で、**順位差の約半分は、これらの変数で説明できていない**。
- 15pt以上ずれる11地点(妙高高原・苗場スキー場・三浦湾展望台・ひるがの高原・爪木崎・鵜の岬海岸・福島潟・見附島・妙高高原(イモリ池)・弓ヶ浜・神磯の鳥居)は、**11件すべてが**新指数で相対的に暗い側(−15〜−30pt。逆向きで最大のみずがき山は +14.8pt)。近傍(0〜20km)の寄与割合は 20〜85%と高い地点が多い。

### 12-4. 最も整合する説明: 測っているものの違い(全天平均 vs 天頂)

- legacy の LPI は**天頂**の人工輝度の比(`light_pollution.py` のコメント: 人工天頂輝度/自然天頂輝度)。新指数の ALR は**全天平均**(論文の定義、式(6))。
- 論文 Table 2(Las Vegas のGarstangモデル実験)では、ALR/ZLR は**距離で変わる**: 3km で 1.87、5km で 2.15、10km で 2.66、20km で 2.96、30〜50km で約3.07、100km で 2.91、170km で 2.33、300km で 1.66。つまり**近傍の光源は天頂に効きやすく(ALR/ZLRが小さい)、中距離(20〜100km)の都市は全天平均に効きやすい**。
- これは上の観察と向きが合う: 近傍の寄与が大きい低地・海岸の地点は、全天平均(ALR)では天頂(LPI)より相対的に暗く、20〜100kmの1都市が大半を占める山間の地点は、ALRで相対的に明るい。
- **検証**: 各地点の距離帯別の寄与を、Table 2 の ALR/ZLR 比で割って天頂に換算した近似(`zlr_equiv`、あくまで診断。Las Vegas の実験値で、日本では未較正)を作ると、LPI との順位相関が **0.951 → 0.965** に上がり、15pt以上ずれる地点が **11件 → 7件**、最大の食い違いが 30.0pt → 26.9pt に減る。7地点の差は、白山 +9.0→+7.6、奥只見ダム +5.5→+4.8、黒部峡谷 +7.6→+6.9、上高地 +3.1→+2.4、柳田 −8.6→−8.6、見附島 −16.2→−15.5、ヤセの断崖 −12.8→−12.1 と、**ごくわずかしか縮まない**。
- したがって、「全天平均と天頂の違い」は方向としては支持されるが、**入れ替わりの大半(特にこの7地点)を説明するには足りない**。残りの要因(近傍の光源の扱い[1km画素・d_min=0.4kmなどの未較正の設定]、legacy 側のモデル・大気の仮定、標高・地形の扱いの違い、衛星データの違い)は、本調査では切り分けられていない。

### 12-5. 結論と注意

- 標高では**ほとんど説明できない**(相関 +0.38、決定係数0.15)。モデルが観測者の標高を扱わないことは本文で確認した。ただし標高が高い地点ほど新指数で相対的に明るい傾向は実在する(上の平均差)。
- 特定の都市との距離では**説明できない**(東京・最寄り都市までの距離との相関は|0.13|以下)。入れ替わった7地点の寄与は、山間側は20〜100km圏の都市(金沢・富山・松本)、湾岸側は近傍(0〜20km)が主で、**「どの都市か」より「近傍か中距離か」**が効いている。
- 最も強い関連は**近傍(0〜20km)の寄与割合**(−0.61)。測っている量の違い(天頂 vs 全天平均)で向きは説明できるが、量は足りない(上記12-4)。
- LP1 の REPORT 6-1 で書いた原因の推測(積雪の無い期間の合成、スキー場の灯り)は、**本調査では支持も否定もできていない**(妙高高原・苗場は近傍寄与が46%・20%と高く、近傍の扱いの違いという説明の方が整合する)。
- これらは**相関と診断**であり、原因の確定ではない。legacy 側の内部(標高・地形・大気の扱い)が公開情報から分からないため、legacy と ALR のどちらが実際の空に近いかは判断できない(実地の観測データが要る)。
- 順位付けへの影響(第11節): 入れ替わりは、数点の減点差が密集した上位のスコアを動かした結果。順位が大きく変わっても、ALR と LPI の差そのものは地点により数ポイント〜十数ポイントの順位差にとどまる。
